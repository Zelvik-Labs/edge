# Zelvik Edge 26.10.4.4

## 修复

- SNI 透传端口只由 ClientHello 分发器接入：此前普通 TCP manager 与 HTTPS manager 会用 `SO_REUSEPORT` 同时监听同一端口，部分连接绕过 SNI 分流并被固定转往首个服务后端；AF_XDP 端口分类与 SNI 索引同步识别这些 TCP 端口。东京节点四组 SNI 出口各测四次：修复前 13/16 正确，修复后 16/16 正确；443 监听由 6 个降为 4 个。
- 配置准入为定时器/I/O 许可持有者提供有界退避，普通准入失败后不再无条件执行 Critical 回收。
- 常驻内存按 cache / bloom 两组分别对各自预算计费，缓存组不再挤占负缓存与 Bloom 额度。
- vendored pingora 工作区提交 `Cargo.lock`（tokio 1.53.1）并在 CI 以 `--locked` 校验：此前该独立工作区每次重新解析依赖，落到产品未发布的 tokio 1.54.1 后，零容量 L4 缓冲在构造阶段 panic，17 个库测试失败。未改动 vendored 源码，运行时语义不变。

## 语义

- 一个 TCP 端口只有一个监听归属：SNI 透传端口不再与普通 TCP manager 共享。
- 内存分组预算互不借贷，单组超预算只回收本组。
- 无缓冲 L4 流（`Some(0)`）仍表示无缓冲；本次只固定依赖解析，不改变缓冲语义。
