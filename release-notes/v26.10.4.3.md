# Zelvik Edge 26.10.4.3

## 修复

- 遥测上传区分可重试与终态失败：网络超时/服务不可用继续退避重试；服务端明确拒绝（如批次早于节点首个 assignment）按终态隔离，不再无限重试。判定优先读服务端稳定元数据码与 `zelvik-retryable` trailer，不解析文案。
- 队首毒批次被隔离时，删除载荷、推进 head、写入持久 loss 记录与 gap 标记在**同一个事务**里提交；崩溃在提交前不会丢数据，提交后不会丢审计。
- 隔离审计只在收到 API 的持久回执后删除，并由正常重放路径重发，重启后可恢复；`collapse_confirmed` 不会误删审计记录。
- 批次按序列化字节切分（上限为 RPC 消息上限的 3/4，6 MiB），对所有 kind 生效；单条超大记录单独进 loss 日志，不拖垮同批数据。
- 节点状态的 telemetry 快照补充 head/tail、ackedAhead、quarantinedBatches、分类失败计数与 lastGapReason。

## 语义

- 数据可以丢，但必须留痕：所有隔离都写入持久 loss 记录并记录 gap 与计数。
- 入集群前的遥测按“产出即隔离”处理，不补历史归属。
- 权限/归属类拒绝按可重试处理：宁可让 lane 暂停，也不销毁已排队的数据。
- 现网已存在的毒头不做自动兼容，现场手工清理一次。
