# Zelvik-Edge 26.11.1

修复指标历史状态累积、遥测耐久交接和 mimalloc v3 选项错位，并补充访问日志访客信息。THP 保持开启。

## 改动

- 自定义指标按配置代、事件分钟和实际模板维度聚合；耐久入队后释放快照行和内存 charge。同分钟新增贡献使用独立实例身份，配套后端先按重试身份去重再求和。
- 精确独立 IP 改为有界的站点/事件分钟/IP 短批次，耐久上报后释放本地集合。日、周、月统计与跨节点、跨分钟的精确 IP 并集由 ClickHouse 计算。内建 request_stat 携带事件分钟与耐久批次身份。
- 移除没有运行时消费者的五分钟/24小时本地重复历史写入，保留旧数据有界过期。
- mimalloc 通过实际链接的 v3 头文件访问具名选项，修正误禁用 arena 分配且未开启 page_reclaim_on_free 的旧配置。应用拥有的 Tokio worker 在 park、繁忙任务轮询、存储/RPC 任务结束边界交出页所有权；分别报告回收计数。
- 遥测确证永久拒绝时，将原始压缩 envelope 和审计同事务耐久隔离；目录同步失败不会伪造成功。重试、隔离与预算背压保持可观测。
- 访问日志独立完成 Geo/UA 分析，补充 ASN、国家代码和设备类别；配套 API 返回运营商属性和节点当前集群。无法识别的 UA 保持 Unknown。

## 升级要求

最低配套 API/Gateway 为 **26.10.5.1**。本次指标契约没有运行时兼容窗口，也没有自动协调旧进程排空和写入隔离。

必须在旧 API 仍运行时完成旧 Edge 在途业务、内存聚合及耐久批次的实际排空，停止旧 Edge 并阻止重启，再停止所有旧 API 写入。启动新 API 完成一次性历史复制并验收后，才能升级 Edge。不能通过删除队列或伪造确认完成切换。已有历史拒绝批次须保留原文并单独处理。

详细步骤见 [升级说明](https://github.com/Zelvik-Labs/edge/blob/v26.11.1/docs/agents/26.10.5-upgrade.md)。此次发行不执行生产部署。

## 验证和已知边界

- 固定维度240次指标交接/重启后零历史残留，精确IP耐久入队后归零，空输入不新增行；状态、预算、拒绝、重试与worker生命周期六组共81项测试通过，0失败/忽略。
- 回收边界正向/移除修复/恢复对照为0→2,015,232→0字节。真实Edge的HTTP/1.1、HTTP/2、TLS与节点状态通过；遥测积压4→0在9.882秒内完成，0存储错误，同一PID。
- 匹配短性能每组90,000请求、0错误：吞吐-1.04%、CPU/请求+1.43%、P99+0.44%，未观察到实质退化。该对照中Edge、负载和模拟后端共用两核限额，绝对req/s和P99不代表生产容量。
- 历史及最新短RSS斜率筛查失败保留；最新六分钟RSS/Anon upper95为234.835/234.827 MiB/h，对照阈值8。短时斜率不能单独证明状态无界，也不能证明长期无泄漏。自动验收现关注有界状态、耐久交接及真实恢复；原斜率诊断保留原阈值供显式手动运行。本次没有运行4h/48h soak。
- Pingora内部runtime尚无回收hook，coversAllWorkers=false。隔离原文计入磁盘预算，满时明确背压。旧表已覆盖的计数、切换前未上报的精确IP身份和粗周期历史的分钟分布无法恢复。

正式源码SHA、五种CPU/架构程序包摘要与多架构镜像digest见 `release-manifest.json`。程序包和镜像复用Actions构建的同一份二进制。
