## 改动与结果

原实现每次 take 和 offer 都执行整个 DashMap 的 retain。现在普通请求触发的
扫描由单调时钟限制为每秒一次；每次取用仍检查该连接的精确 120 秒 TTL，
满池及显式内存回收仍立即扫描。容量压力扫描前释放 shard guard，4096 个空闲
配额保持硬限制，替换条目保留原配额。

| 实际空闲连接数 | 旧 take+offer 中位数 ns | 新中位数 ns | 五轮配对耗时变化中位数 |
|---:|---:|---:|---:|
| 1 | 290.07 | 275.29 | -5.15% |
| 16 | 517.26 | 283.97 | -45.29% |
| 256 | 5,453.11 | 310.06 | -94.31% |
| 1024 | 31,833.65 | 412.07 | -98.69% |

40 个独立进程、800 个计时块全部保留。每个连接先真实握手并完成正文、重复响应头、
trailers/FIN 校验，再进入计时；计时仅包含生产 take/offer 和正常 key clone。
计时后逐一核对 QUIC/driver 身份、配额和连接关闭。没有模拟健康状态或替身协议对象。
五轮采用交错顺序，实际允许的 CPU 身份用于绑定；整个进程观测窗口均无 host steal。
每格样本未筛选，1 连接格的首轮较其他轮更快也原样保留。

两份 release library test 可执行文件先完成构建再测量，只有连接池实现不同，
旧文件精确取自 `b5bc67e`。这是 System allocator、测试 unwind 的库测试程序，
不能当作使用 mimalloc、panic=abort 的生产 Node 容量。配对百分比由逐轮比值计算，
不等于两个独立中位数的比值。

## 验证和边界

22 个 origin H3/pool/state 相关测试通过，另一个被标记 ignored 的性能探针由实验
显式执行 40 次。新增控制覆盖扫描间隔并发争抢、延后扫描时拒绝过期键、满池即时
回收、健康条目替换配额和容量不足拒收；原有真实网络异常与超时检查保留。

已修复：请求频率乘连接池规模的重复扫描。
仍待完成：同连接活跃请求多路复用、最新整机协议状态矩阵及长期稳定性测试。
设计限制：当前仍是按请求独占取出的上下文；本轮只改善 H3 回源连接池，客户端
H3、H1 回源场景不会因此直接获得相同收益。
经审批的功能降级：无。
