# Edge 下游 TCP 小写缓冲接入

新增仅在创建流时设置容量的 Pingora TCP 构造器，Edge 继续使用具体 L4Stream 和现有 socket digest，选择读 0/写 1460B。未套额外 IO 包装，明文缓存 sendfile 仍可识别；PROXY/SNI 检查和 passthrough 分流仍发生在构造前。用户已明确授权这处 upstream 构造器及相邻测试、项目接入与内存账本改动。

HTTP 连接估算由 32KiB 增加 1460B，包含缓冲的整个连接生命周期成本；内存紧张时估算允许的连接数相应减少。不增加每连接 64KiB 读缓冲，不关闭统计、WAF、缓存、协议或持久化。

新增回归覆盖实际 TCP 的多次小写/flush、原生类型与 peer digest、旧 From 与显式零缓冲、不读取客户端下的有限发送缓冲压力及取消后续写、sendfile 的缓冲头先于正文与偏移长度。这些回归已由最终 CI 通过，见下方正确性门禁。

已有同 ELF 裸框架四轮配对数据：H1/H1-TLS 吞吐 +10.78/+10.60%，CPU/响应约 -8.54/-8.56%；这些不是 Edge 节点收益。新的独立节点对照固定前版 4613a6b8、候选 60cf30ce，只允许三个生产文件不同，先构建并留存四份实际 Edge/controller ELF，再测 before/after/nginx/OpenResty。

实测矩阵为 H1/H1-TLS/H2/H3 × HIT/MISS/OFF × reuse/fresh × 四目标 × 四轮，共 384 格；每格全新进程和 tmpfs，1KiB、32 并发，复用 5 秒、新连接 2048 请求。核对全部正文/状态/协议/长度与回源契约、256 个 Range 控制、48 个 wrong-CA 控制，CPU/有效响应、P99 和内存与负向轮次一起报告。错误不会被重试覆盖。

已完成：构造器、原生入口、内存估算、完整回归、严格节点对照和原始归档独立复算。设计限制：云短窗口和固定负载不代表长期稳定性，H3 不经过该 TCP 构造器，作为回归对照。经审批的功能降级：无。

本次确定的节点收益主要在 H1/H1-TLS 命中复用：四轮吞吐分别均为正向，配对中位 +19.01%/+18.37%，CPU/响应约 −15.58%。H2 HIT/reuse 为 +2.15%，MISS/reuse 为 −0.52%；H3 HIT/fresh 为 −1.95%，完整负向轮次不删除。大部分 H1/H2 条件仍低于竞品，H3 HIT 的客户端接近两核预算，不能据此判断代理容量已超过。测量输入是固定候选 ELF；最终发行包由标签流水线用各 ISA 的发布参数另行构建，不把候选的 RPS 冒充最终安装包的实测。
