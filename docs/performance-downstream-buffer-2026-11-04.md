# Edge 下游 TCP 小写缓冲接入

新增仅在创建流时设置容量的 Pingora TCP 构造器，Edge 继续使用具体 L4Stream 和现有 socket digest，选择读 0/写 1460B。未套额外 IO 包装，明文缓存 sendfile 仍可识别；PROXY/SNI 检查和 passthrough 分流仍发生在构造前。用户已明确授权这处 upstream 构造器及相邻测试、项目接入与内存账本改动。

HTTP 连接估算由 32KiB 增加 1460B，包含缓冲的整个连接生命周期成本；内存紧张时估算允许的连接数相应减少。不增加每连接 64KiB 读缓冲，不关闭统计、WAF、缓存、协议或持久化。

新增回归覆盖实际 TCP 的多次小写/flush、原生类型与 peer digest、旧 From 与显式零缓冲、不读取客户端下的有限发送缓冲压力及取消后续写、sendfile 的缓冲头先于正文与偏移长度。尚未把这些测试的编写视为运行通过，Rust 门禁通过 GitHub Actions 执行。

已有同 ELF 裸框架四轮配对数据：H1/H1-TLS 吞吐 +10.78/+10.60%，CPU/响应约 -8.54/-8.56%；这些不是 Edge 节点收益。新的独立节点对照固定前版 4613a6b8、候选 60cf30ce，只允许三个生产文件不同，先构建并留存四份实际 Edge/controller ELF，再测 before/after/nginx/OpenResty。

计划矩阵为 H1/H1-TLS/H2/H3 × HIT/MISS/OFF × reuse/fresh × 四目标 × 四轮，共 384 格；每格全新进程和 tmpfs，1KiB、32 并发，复用 5 秒、新连接 2048 请求。要求全部正文/状态/协议/长度与回源契约、256 个 Range 控制、48 个 wrong-CA 控制，CPU/有效响应、P99 和内存与负向轮次一起报告。错误不会被重试覆盖。

已实现：构造器、原生入口、内存估算、回归和严格节点比较流程。仍待完成：完整 CI 与真实节点数据，未声明生产收益。设计限制：云短窗口和固定负载不代表长期稳定性，H3 不经过该 TCP 构造器，作为回归对照。经审批的功能降级：无。
