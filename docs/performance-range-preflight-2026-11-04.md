# 缓存准入：将完整对象预检查延后到 Range 请求

运行时 `fe89411dfaf86dd2547f6714ed8435803277c3a4` 已将完整对象的 MD5、元数据读取和已存响应头验证
限制到实际带有非空文本 Range 的请求。普通请求不再支付这项只用于选择完整/部分对象的预检查成本。
当前尚无本轮吞吐数字；不能把之前 CPU 样本的占比直接换算成速度提升。

## 已实现

`cache::partial::select_cache_range` 接收一个延迟执行的完整对象探测。
没有 Range 时直接返回；有 Range 时仍先检查完整对象，再应用部分缓存策略和单 Range 语法。
key、过期、状态、压缩、共享缓存安全头和内容编码的原有谓词完整保留在探测中。
存储层原本的回放校验继续执行。没有删掉缓存验证、统计或协议防护。

回归要求普通请求绝不调用探测闭包；32 种组合覆盖前缀、后缀、开放区间、大小写、无效/多区间语法，
以及完整对象与部分缓存开关的优先级。完整对象可用时仍由 Pingora 解释 Range，未偷偷改成只支持部分存储的语法子集。

依据来自[实际二进制 CPU 归因](performance-http-cpu-2026-11-04.md)：H1 HIT 的缓存准入包含占比为 17.48%，
其中已存响应头校验为 5.31%；两者有包含关系，不相加，也不构成新节点性能数字。

全矩阵通过时应有 128 项控制。目标独立运行、每格新进程；所有编译在计时前结束。

## 仍待确认与设计限制

需要等原始记录验证后才能报告 paired RPS、CPU/request 与 P99，失败格不会进入完整格中位数。

也不替代 24/72 小时稳定性。当前没有超过 Nginx/OpenResty 的新结论。
