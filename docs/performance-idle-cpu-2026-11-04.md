# 固定 ELF 的空闲与带载 CPU 诊断

futex 短窗口大多是 Mace 后台等待，不能由等待次数推导 CPU。增加独立只读观察：实际固定 ba474 Edge、旧 3b25 裸 Pingora、nginx/OpenResty，H1 OFF/复用、1KiB、32 并发、5 秒真实原生客户端负载，四目标各独立启动，两轮顺序相反，共八格。

每格在正文/协议/长度 preflight 后、负载前采集 10 秒；负载结束并做正文校验后再采集 10 秒，每秒一次。观察器直接读只读 host cgroup 和 /proc 的 CPU/内存/线程计数，不在代理容器内执行采样命令。另保留负载前后相同进程的计数、实际 CPU 配额、原始所有快照与 HTTP 记录；进程 starttime 改变直接失败，线程退出/新生单独记录，仅存活线程差值不冒充全部线程 CPU。

继续核对实际 Edge/controller/client 与裸框架 ELF，保存实际竞品 ELF、源站请求与连接复用、失败和完整性控制。全部镜像准备在观测前完成，不构建 Rust。边界测试覆盖带括号/空格的线程名、进程身份复用以及线程退出不能隐藏整体进程 CPU。

状态：准备 GitHub Actions 执行，尚无数值结论。CPU 不扣除空闲参考，不将观察器下的 RPS 作为新容量排名；10 秒不代表背景稳态，负载后窗口包含持久化/清理等真实工作，后台网络任务不被关闭，线程名不能自动等同某个库的调用栈。

未修改 upstream、生产指标或持久化策略，不依赖待确认的小写缓冲构造器方案。设计限制：旧固定 ELF、H1/OFF/复用、短云窗口，不提供最新 Edge/H3/长期稳定性或可删除业务功能的收益。经审批的功能降级：无；未部署。

## 首轮负载前的观测框架错误

[41818510632](https://github.com/Zelvik-Labs/edge/actions/runs/41818510632) 的三项计数边界测试、实际 ELF 校验和镜像准备通过，但八个子驱动都在写 manifest 前读取 /sys/fs/cgroup/cpu.max 失败，没有启动实际负载；不能算八格性能失败或成功。

原因是本观察器显式使用 host cgroup namespace，根 cgroup 不具有 cpu.max。原通用框架假设根挂载就是自身的 private cgroup。现在仅允许调用方显式提供实际父 cgroup 路径，本观察器从 /proc/self/cgroup 解析并使用只读 host 挂载；其他调用方默认路径保持原值。缺失的实际配额文件继续报错，不伪造 unlimited。增加 host 根无配额和实际子组缺文件两项边界测试。
