# Edge 26.10.5 与 suite 26.10.5 升级说明

本文件描述升级要求，不表示已完成发行或生产部署。发行验证结果另附源码 SHA。

## 修复范围

- 修正 mimalloc v3 的选项访问：通过链接库自己的头文件获取具名选项，开启 page_reclaim_on_free，恢复允许 arena 分配的默认值。
- 自有 Tokio runtime 的线程使用启动、park、退出回调执行回收；Pingora 内部 runtime 尚无回调，状态继续报告 coversAllWorkers=false。
- 自定义指标按配置代、事件时间及实际模板变量聚合；累计快照携带耐久 revision 和行实例标识，ClickHouse 使用节点身份、实例 hash 和 revision 处理重试、乱序与多个节点贡献。分钟桶清理后才完成的长请求建立新实例，其增量与旧实例总量相加，不覆盖此前累计值。
- 遥测按稳定错误码区分可重试与确证无效；永久拒绝批次的原始压缩 envelope 和审计一起耐久隔离，收到 gap 收据后仍保留原文。
- 访问日志补充 ASN、国家代码、设备类别及独立于指标的分析生命周期；API 返回已有运营商属性和当前集群，控制台节点筛选由服务端执行。无法识别的 UA 保持 Unknown。

## 指标契约切换

旧批次不能无条件改写成新快照：旧 API 可能已提交但确认未落盘，改用新 hash 重发会与历史复制重计；旧 keepKeys 还可能依赖接收端状态。离线转换必须核对原始批次的接收结果，不能猜测窗口、键或累计值。

当前只自动执行 ClickHouse 建表和一次性历史复制（含 marker 校验）；下列切换顺序尚无自动协调实现。API 不会自动排空旧 Edge spool 或暂停其它旧 API，节点升级任务也不会校验这次指标契约的前置状态。普通滚动升级不能代替该顺序。本节是当前实现的部署限制，不是已经完成的自动升级功能。

本轮没有运行时兼容窗口。最低配套版本为 suite API 26.10.5 和 Edge 26.10.5。新增字段为 UploadMetricStatsRequest.revision（9）、windowStart（10）、windowEnd（11），区间为 epoch 秒的 [start,end)。新发送端不使用 keepKeys。

1. 在旧 API 仍运行时，排空所有旧 Edge 的 metric_stat 待发批次。停止旧指标写入并确认在途请求完成，之后保持旧写入暂停直到切换结束。已有历史拒绝批次不能假确认、删除或忽略；若无法排空，应先保留完整原文并单独解决，停止本次生产切换。
2. 停止所有旧 API 指标接收写入，再启动新 API。不能让新旧 API 同时接收指标：新 API 首次创建 metric_stat_snapshot，并一次性从 metric_stat FINAL 复制仍存活的历史行；迁移 marker 记录版本及 SQL 校验和。首次复制之后才写入旧表的行不会自动再次迁移。
3. 确认迁移及 API 健康后，将 Edge 升至 26.10.5，再恢复指标采集。Edge 不得先升级：旧 API 不理解累计 revision，可能按接收时间让迟到旧快照覆盖新值。
4. 核对同窗口的累计值、两个节点求和、待发队列和新表结果。控制台可与 API 独立升级至 26.10.5。

新 API 遇到 revision=0 时返回 telemetry.metric_snapshot_version_required 和 retryable=true。原始批次继续留在 spool；它不会被当作累计快照，也不会被确认或丢弃。现有 spool 按 core/detail 两条 lane 排序，残留旧批次可能占用 detail 队头并影响后续批次的连续回收。此行为不等于自动转换旧数据。

## 历史与回滚

旧 metric_stat 表不删除、不重写。迁移只复制旧表 FINAL 仍保留的行；旧 ReplacingMergeTree 已覆盖掉的节点或增量贡献无法恢复。历史行保留 event_time，无法可靠推导的 window_start 为 0；查询从新表读取迁移历史和新快照，使用 FINAL 后按系列求和。

切换开始后应前滚修复。不能直接恢复旧 API/旧 Edge 并继续同周期指标写入：旧表不会接收新快照的迁移结果，重置或删除 Edge checkpoint 还会生成新 epoch，使当前累计值再次计入。回退前必须暂停采集，保留新表、原始 spool、checkpoint 和隔离原文，并单独确定数据转换方案。

## 验证和容量边界

短时回归仅验证本次输入、进程和观察窗口，不能证明长期无泄漏。生产部署不属于本次发行动作。

隔离原文计入磁盘预算，未实现自动删除或离线转换工具。归档达到预算时会明确背压，不能以无限磁盘保证无限保留。checkpoint 无法读取或写入时保留原文件并报告错误，不通过重置 epoch 伪造恢复。

内建 request_stat 仍沿用 flush 时的 day/month，跨午夜或排队延迟的日期归属问题尚未修复；本轮的事件时间窗口修复覆盖自定义 metric_stat。该限制不能被表述为所有统计时间归属均已修复。

日志的集群表示节点当前的有效成员关系。系统没有可返回的分组模型时，分组保持缺失；不会构造默认分组或猜测浏览器、系统、ASN。
