# 内存预算快照的并发发布与读取成本

当前memory_snapshot读取多个Relaxed原子字段，前后用cached_at_millis相等来判断一致性。
writer在现有Mutex下先把时间戳置0，写字段，再恢复本轮毫秒；快速重复刷新可使用相同时间戳，读取窗口存在ABA。
此外时间戳恢复为Relaxed写，不能直接当作Acquire读所需的Release发布。cached_generation虽另有Release，但该快照读者没有读取它。
这是待验证的发布协议问题，尚未量化线上触发率、错误预算或性能影响。

先在独立组件用与原代码相同的原子操作顺序重现同毫秒混合读；不通过修改时钟或关闭内存治理来规避。
候选使用独立序号：writer在原Mutex内标奇数，Release fence后写字段，最后Release发布偶数；reader以Acquire读偶数、读取字段，再Acquire fence并验证序号。
不复用已有limits缓存世代的奇偶语义，不改变失效逻辑；中断writer不在Drop中发布不完整状态，后续持锁writer可恢复。
序号为64位环绕计数，假设同一次读取期间少于2^63次发布；不是无限大数学整数。

Loom使用同一候选函数体替换原子实现，单writer穷举调度、两writer在Mutex下验证至多2次抢占，范围在输出中明确。
两个负向控制必须暴露相同一致性断言：原时间戳协议，以及缺少fence的序号协议，避免测试只验证一个不会出错的顺序模型。
组件计时另行构建运行，不与模型重叠：2/20字段纯读取、每1024/16次读取发布一次，各八轮平衡顺序、二十块。
这些是发布协议成本，不含真实kernel读取、预算计算、压力回收或节点性能；所有回退和steal都保留。
