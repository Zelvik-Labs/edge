# 缓存优化后的实际 HTTP CPU 复核

响应头校验组件耗时约降 35%，独立节点吞吐却只变化约 0～1%。本轮重新对实际已测量二进制采样，
为下一项优化定位当前热点，避免继续套用 Range/响应头优化之前的采样比例。

手动 architecture-profile 工作流增加 headers 选择，固定使用已完成 192 格对照的 `ba474745fae3c08332d9e0862d9d5650550664ff`。
它包含 Range 预检查、上下文 move 及响应头逐字段校验，不包含后来的共享 QUIC 维护/可写等待改动。
复用原始客户端；Edge/controller 从原 artifact 取出并逐项验证实际 SHA256、来源、尺寸，采样前不重新编译。

H1/H1-TLS/H2 × HIT/OFF/MISS × 两轮，共 18 个隔离节点条件，每格 20 秒、199 Hz user CPU 采样。
每次传输仍检查协议、正文、缓存状态与连接行为；丢失样本和宿主 steal 继续记录。
符号化栈用于归因，包含式热点可能重叠，不能相加；被采样流量的吞吐不进入容量排名。
公开证据继续按允许列表收集，排除原始 stack 内存、测试私钥、运行时 overrides 与存储目录。

首轮 [Actions 41766617084](https://github.com/Zelvik-Labs/edge/actions/runs/41766617084) 在启动首个被采样节点时退出 126，尚未产生正式采样格。
原因是 prepare 在容器中再次 copy2 归档文件，把宿主先前设置的执行权限恢复成归档默认权限。
现将权限恢复放到每次 prepare 的哈希校验后，保证重复准备也可执行；错误批次保留，不作为性能结果。
[修复后 Actions 41767019693](https://github.com/Zelvik-Labs/edge/actions/runs/41767019693) 已通过，并重新核验全部归档、实际三个二进制、每次传输及每个符号化样本。
已修复项见此前缓存报告；未解决的节点吞吐差距和 QUIC 互操作错误仍保留。经审批的功能降级：无。


## 结果与下一项优化

18/18 个条件通过，4,961,504 次成功响应、零传输错误；43,074 个样本、零丢失、宿主 steal 为零。
下表按两轮样本数加权，是包含式栈归因，可相互重叠，不能相加；占比变化也不等于相同幅度的耗时下降。
这是新二进制的当前热点，不把不同实例中的前后百分比差写成因果收益。

头处理包含 Pingora/http 库解析与编码，不能直接按此占比声称 Edge 单个函数可全部省去。
glibc 未解析叶子、vDSO 及其他符号化限制在逐组 unknown_leaf_percent 中完整保留；零丢样不意味着每个调用都能归因。
