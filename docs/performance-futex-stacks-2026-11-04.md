# futex 操作与调用者归因

此前四目标计数中，固定 ba474 Edge 的 H1/H2 OFF 约有 1.93/1.81 次 futex/有效响应，而裸 Pingora 接近零。现在完成两组有界调用者采样及独立原始记录重算：**样本绝大多数来自 Mace 后台等待，不能把原来的计数/响应比值归因成每请求统计唤醒，也不能由等待事件数估计可回收 CPU。**

## 有界窗口的实际结果

固定同一 ba474 实际 Edge/controller/client，H1/H2 OFF/复用各两轮，20 秒真实 HTTP 负载；perf 只保留约 100ms 的 syscall tracepoint 用户栈，公开脱敏操作值/符号链，排除原始参数和 perf.data。逐请求状态/协议/长度、完整性、实际 ELF、失样及资源门不放宽。

| 运行 | 窗口条件 | 完整格 | 有效响应 | HTTP 错误 | 样本 | 丢样 |
|---|---|---:|---:|---:|---:|---:|
| [41808935453](https://github.com/Zelvik-Labs/edge/actions/runs/41808935453) | 与客户端启动并行，未验证采样开始时已有响应 | 4 | 556,865 | 0 | 1,265 | 0 |
| [41812436186](https://github.com/Zelvik-Labs/edge/actions/runs/41812436186) | 两个原生客户端均先输出完成记录，再启动 perf | 4 | 462,134 | 0 | 1,246 | 0 |

第二组另保存各客户端记录文件在 perf 进程包络开始/结束的字节数与单调时钟，独立读取原始压缩 TSV 对应前缀，验证两个客户端完成行数均继续增长。进程启动/回收包络约 1.17 秒，实际事件时间跨度为 0.1033～0.1049 秒，不能把包络时长或整个 20 秒当作完整采样窗口。客户端通过 host taskset 直接启动，先前将同步误差猜作 Docker 启动的说法不成立。

以下是互斥调用者组，按保留栈中的最近相关模块分类，计数仅限这些短窗口：

| 调用者 | 启动并行窗口 | 已有客户端完成记录的窗口 |
|---|---:|---:|
| Mace CheckpointTask | 1,129 | 1,113 |
| Mace CollectorSignal | 123 | 125 |
| Mace 其他 SharedState | 6 | 6 |
| Node memory_reclaim | 1 | 2 |
| Tokio blocking 等待/唤醒 | 6 | 0 |
| 合计 | 1,265 | 1,246 |

第二组全部 1,246 样本操作为 137，即 FUTEX_WAIT_BITSET_PRIVATE。第一组另有 3 次 WAKE_PRIVATE、3 次 WAIT_PRIVATE，其余 1,259 次同为 137。没有看到某个调用者的样本并不证明其没有成本；这也不覆盖全部线程/请求/事件。

只读核查 mace-kv 0.2.0 的 map/flush.rs：checkpoint_thread 使用 recv_timeout(Duration::from_millis(1)) 后执行 process_task，支持继续调查空队列的后台定时唤醒。Node 的 src/metrics/storage.rs 保持 backpressure 和持久化策略；当前未改库、未删除 checkpoint/GC、未把周期加长来制造结果。后续若优化，应在空闲时阻塞、退出时显式唤醒，保持待处理任务/退出持久化语义，再分别测空闲 CPU 与带载吞吐；当前没有实现或 CPU 收益结论。
