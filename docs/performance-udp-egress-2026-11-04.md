# UDP 出口背压时避免先复制再拒绝

共享 H3/UDP 的 channel 发送旧路径先复制借用的正文，再检查有界队列是否满或已关闭。
因此真实背压时会为必定失败的发送分配和复制载荷；此前可写等待修复减少空转，本候选进一步减少每次拒绝的工作。

第一候选先 try_reserve，获得容量后再构造载荷；容量满继续返回 WouldBlock、关闭继续返回 BrokenPipe，错误文本保持。
已有所有权的 Bytes 不复制，入队仍保留地址和单调时间戳，容量与数据包所有权不变。
尚未进入生产，不依据源码推断吞吐收益；原 io::Error 的分配保持，不声称整条拒绝路径零分配。

组件以不可变生产 `c310473` 为基线，真实 Tokio mpsc 容量 1；覆盖 64/1200/65507 字节借用正文和 1200 字节 owned，
分别测 Ready/Full/Closed，共 12 条件。正文、来源地址、owned 指针、既有队列内容、排空恢复与关闭均做控制。
八轮交替配对，每条件每轮二十块；分配与计时分开构建，记录 steal，排除编译重叠。
Ready 计时包含取队列，不代表完整 Edge 或真实 AF_XDP ring 吞吐。

首轮 Actions 41767471706 在提取不可变基线前失败：默认浅克隆没有基线提交，未编译、未计时，无组件结果。
现显式取得完整历史，并在提取前保留 setup 来源元数据，确保准备失败也有证据。
状态：两项组件候选已核验，均未进入生产；下文保留正常发送退步。
未修改 vendor、队列上限或错误语义。经审批的功能降级：无。

## 第一候选实测与保留代价

[Actions 41767617510](https://github.com/Zelvik-Labs/edge/actions/runs/41767617510) 已通过并核验：24 项版本/场景控制、3840 个计时块、零宿主 steal。
Full/Closed 的 borrowed 分配每次 4→3，分别省去正文大小的字节；原错误对象的三次分配保持。
但正常 copied-64/1200 分别慢约 5.12%/7.42%，因此当前不进入生产。

保留 [reserve-first 源码](../benches/support/udp_egress_reserve_candidate.rs)。不同云实例的组件数值不用于节点排名。

第二候选先读 is_closed/capacity 快照拒绝已不可用队列，成功路径继续保持原复制及 try_send 顺序。
最终准入仍由 try_send 判断；并发抢占时可能在复制后仍遇到 Full，不宣称所有拒绝都消除复制。
owned 路径保持原实现，不预报其收益。继续以相同十二条件和八轮配对验证正常发送代价。

常态复制仍有额外快照读取的成本，当前保留候选，优先处理真实节点采样中更大的正常路径成本。
owned 的小幅波动不解释为源码已优化，第二轮与第一轮的不同实例绝对耗时不直接比较。
归档 `13294045455`：536,386 字节、37 文件；复核器使用 snapshot 参数，检查实际二进制及所有原始数据。
两项候选都不作为生产吞吐提升、真实 XDP 收益或长期稳定性结论。

## 第三候选：仅改变错误载荷表示

前两种方案都为正常 copied 发送增加了工作。第三候选保持原始成功发送体和正文复制顺序，
仅把 io::Error::new 的字符串载荷改为私有零大小错误类型：Display/Debug 和 ErrorKind 保持，仍无 OS errno。
这不是删除错误信息；原始字符串、动态错误载荷和外层 io::Error 的堆分配有机会减少，但外层自定义错误仍可能分配。
增加 Debug/errno 控制，继续测十二条件、八轮配对及所有权，不预报正常或拒绝路径收益。
旧 reserve-first/snapshot 源码与证据都保留，第三候选亦未接入生产。
