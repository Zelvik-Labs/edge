# UDP 出口背压时避免先复制再拒绝

共享 H3/UDP 的 channel 发送旧路径先复制借用的正文，再检查有界队列是否满或已关闭。
因此真实背压时会为必定失败的发送分配和复制载荷；此前可写等待修复减少空转，本候选进一步减少每次拒绝的工作。

候选先 try_reserve，获得容量后再构造载荷；容量满继续返回 WouldBlock、关闭继续返回 BrokenPipe，错误文本保持。
已有所有权的 Bytes 不复制，入队仍保留地址和单调时间戳，容量与数据包所有权不变。
尚未进入生产，不依据源码推断吞吐收益；原 io::Error 的分配保持，不声称整条拒绝路径零分配。

组件以不可变生产 `c310473` 为基线，真实 Tokio mpsc 容量 1；覆盖 64/1200/65507 字节借用正文和 1200 字节 owned，
分别测 Ready/Full/Closed，共 12 条件。正文、来源地址、owned 指针、既有队列内容、排空恢复与关闭均做控制。
八轮交替配对，每条件每轮二十块；分配与计时分开构建，记录 steal，排除编译重叠。
Ready 计时包含取队列，不代表完整 Edge 或真实 AF_XDP ring 吞吐。
