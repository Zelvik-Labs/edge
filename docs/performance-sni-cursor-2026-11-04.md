# SNI 第二阶段：跨记录读取与小正文栈缓冲

最终候选 `471f95a5d108bad4e0238444e7cdc1443449f90a` 消除了第一轮完整分片的主要退步：
大 ClientHello 只跨 record 读取字段，已完整到齐且正文不超过 256 字节的 ClientHello 使用有界栈缓冲。
普通单 record 仍借用输入；不完整输入不分配。下述数字都是解析组件结果，不是整条 SNI 连接吞吐。

[四版本 Actions 41706664208](https://github.com/Zelvik-Labs/edge/actions/runs/41706664208) 已通过，
32 个独立计时进程、3200 个原始块和 64,203 个逐输入结果已在本地复算。
最终完整 CI 在分支 `perf/sni-hybrid-20261104` 运行，完成前不把原生 AF_XDP 验证算作通过。

## 已修复

[第一轮](performance-sni-parser-2026-11-04.md)避免不完整输入按声明长度申请内存，但完整分片仍需扫描后拼接整个正文。
第二阶段保留完整 record 校验，大正文用无分配 cursor 跳过版本、随机数、密码套件和无关扩展，
只返回 SNI hostname；hostname 跨 record 时收集的 Vec 直接转为 String，再就地转 ASCII 小写。

纯 cursor 候选 `52687f9` 在小 ClientHello 附带额外数据时比第一轮慢 29.31%，因此继续增加小正文栈缓冲。
栈缓冲严格最多 256 字节，只在完整性校验之后使用；大正文不会为 padding 拼接整条握手。
其函数单独禁止内联，以避免把固定 scratch 放进普通单记录路径的栈帧。

四版在同一 runner 上比较：原始 `ac46a48`、第一轮 `b4d6355`、纯 cursor `52687f9`、最终混合候选 `471f95a`。
以下 ns/次为各版本进程中位数，百分比为八组配对比值的中位数，两种计算不要混用。

| 输入 | 原始 | 第一轮 | 纯 cursor | 最终候选 | 最终相比原始 | 最终相比第一轮 |
|---|---:|---:|---:|---:|---:|---:|
| 普通单 record | 33.68 | 33.60 | 28.68 | 29.25 | -13.47% | -13.10% |
| 完整分片，8 KiB padding | 140.79 | 151.25 | 79.24 | 77.60 | -45.01% | -48.63% |
| 不完整 2 KiB 首段 | 49.12 | 4.78 | 3.21 | 2.91 | -94.14% | -39.71% |
| 最大声明长度，数据未到齐 | 30.47 | 4.78 | 3.25 | 2.92 | -90.41% | -38.86% |
| 小 ClientHello 附带额外 8 KiB | 142.42 | 56.29 | 73.96 | 43.33 | -69.56% | -23.11% |

独立分配探针中，最终版本的三个完整输入均只有返回 hostname 的 **1 次 / 11 字节**申请；
不完整和极端声明输入均为 0。原始完整大分片为 2 次 / 8274 字节，尾随数据场景为 2 次分配加 1 次 realloc / 8337 字节。
这些是分配请求量；栈上的有界 scratch 不计入 allocator，也不能据此宣称整个节点零分配。

四版对 64,203 个输入返回完全相同的结果，包括逐前缀、确定性变异、所有受支持的小握手切分位置、
空中间 record 及其逐位变异。最终 9 项生产测试还覆盖 UTF-8 跨 record、无效 UTF-8、空 hostname、
大/小正文的所有切分位置、逐字节 record、255/256/257 字节边界和现有 ServerNameList 边界行为。
没有借性能重构悄悄收紧或放宽原有分类。

## 仍存在

相对纯 cursor，最终版本的单 record 配对中位数慢 **1.82%**，完整大分片快 2.11%，尾随数据场景快 41.46%。
保留这项局部取舍，不宣称所有候选、所有输入都单调变快；最终版本对本轮原始基线的五档结果均更好。
SNI 解析通常只发生在连接开始，不能用该收益解释或填平普通 HTTP 每请求 CPU 差距。
真实 SNI 端到端握手、慢分片及多连接吞吐仍需独立测量。

## 设计限制

Rust 1.99.1、x86-64-v2、opt-level=3；同一 CPU 上两轮 Williams 顺序设计，每版在各位置出现次数相同，
每周期中各版本跟随其他版本的次数也相同。没有删除离群值，完整八组配对保存在证据中；记录 host steal 为零。
计时使用正常 System allocator，分配计数使用不同二进制；全部构建在测量前完成。
原始版本在不同 runner 上的纳秒数明显不同，所以只使用本次同机配对，不拼接不同运行的绝对耗时。
首次纯 cursor 的完整 18 进程 / 1800 块及其退步也保留，没有用最终候选覆盖中间结果。

## 经审批的功能降级

无。SNI 转发、前缀回放、连接保护和统计保持；未修改 vendor、TLS 校验、peek 超时或截断策略。
