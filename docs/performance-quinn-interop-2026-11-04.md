# Quinn 与两种 libcurl QUIC 客户端的互操作

[协议诊断](performance-quinn-diagnostic-2026-11-04.md)观察到 OpenSSL 客户端本地发出 10 次 `KEY_UPDATE_ERROR`。
本轮将同一份 C 客户端分别链接同版本 Debian libcurl 的 OpenSSL 与 GnuTLS/ngtcp2 实现，进一步约束故障范围。
第一轮已产生错误及不完整批次；不能认定某一端已修复。

保持原始 Edge/controller 二进制、编译参数、客户端代码、正文、请求数量、QUIC 参数和缓存状态一致。
两个 libcurl 软件包的完整 Debian 版本必须相同，否则在测试前失败；实际客户端及动态库均保留哈希与文件。
OpenSSL/GnuTLS/GnuTLS/OpenSSL 顺序各独立执行 32 KiB HIT、16,384 次 fresh 尝试，共 65,536 次计划尝试。
两种客户端均不启用诊断 trace，错误继续保留并导致工作流失败。

本地已成功编译两种客户端并验证分别加载 OpenSSL 原生 QUIC、GnuTLS + ngtcp2；这只证明构建与后端选择，
不是 H3 网络验证。[Actions 41759827134](https://github.com/Zelvik-Labs/edge/actions/runs/41759827134) 已完成并返回失败，错误和被终止的客户端部分输出均保留。
不同客户端实现不做服务端吞吐排名，也不据零错误宣称长期稳定。

仍待完成：Actions 原始数据、错误归类及与 key phase/HANDSHAKE_DONE 诊断相互验证。
经审批的功能降级：无；不更改生产传输、防护或密钥更新策略。

## 第一轮：不完整的 GnuTLS 对照

两种 libcurl 均为 `8.14.1-2+deb13u7`，OpenSSL 3.5.7；GnuTLS 3.8.9 + ngtcp2 1.11.0。
OpenSSL 两轮完整完成 32,768 次尝试，10 次 curl 56、32,758 次成功。
GnuTLS 两轮均达到原测试进程期限而被终止：已写出的 18,300 条完整记录全部为 H3/HTTP200、32 KiB 正文、一次新连接，
没有已写出的错误，但不完整批次仍判失败，不计作 32,768 次通过；未写入缓冲区的结果未知。
首条 GnuTLS 请求约 0.52～0.58 秒，客户端成本使原定请求量无法在期限内完成。

[仓库证据](evidence/quinn-interop-2026-11-04/)包含原始软件包版本、实际客户端及依赖库哈希、部分记录统计和可移植复核器。
公开 artifact `13289573635`：100 文件、2,454,854 字节；实际二进制/动态库 artifact `13290491360`：41 文件、29,139,364 字节。
原 CI 的 GnuTLS 成功数零表示没有完整可核算的格，不能解释为零有效响应。
补充校验明确列出四份部分输出，避免把“无错误的部分记录”写成完整成功。

## 测试 CA 范围控制

下一轮两客户端都显式使用测试 CA 文件，并清除默认系统 CA 目录路径，以排除额外信任目录加载的影响。
此选项仅用于本互操作测试；普通压测客户端默认行为保持。
证书链和主机名校验继续开启，受信任范围更窄；每个实例另用错误 CA 做一次负控制，必须返回 curl 60。
仍用相同请求数量和原期限，若再次超时则继续保留失败，不据部分记录宣称兼容性通过。
系统 CA 目录是否解释主要成本，需要新一轮实测，当前只作为待验证假设。

## 同一 OpenSSL 客户端的组选择控制

增加手动 `groups` 模式：default/X25519/X25519/default，四格均使用同一个 OpenSSL 客户端二进制。
测试 CA、连接数、正文、请求数量和服务端仍固定；仅通过客户端公开选项限制支持组。
该模式开启有界诊断，直接解析 ServerHello 的公开 key_share 组号，按槽记录观察次数与组号变化。
解析器不保存公钥正文、不递归调用 SSL API，字段本身也不作为认证证据。
X25519 格必须实际观察到组号 29，不能仅凭设置参数声称对照生效。

这是受控客户端实验，不改变生产 TLS 默认组或密钥更新策略。握手报文大小与时序仍可能不同，
相关吞吐不参与服务端排名。测试尚未完成，不能据默认组名称预判错误原因。
ServerHello 元数据、截断和组号观察的 C 控制已通过 ASan/UBSan；GitHub Actions 将执行网络对照。
