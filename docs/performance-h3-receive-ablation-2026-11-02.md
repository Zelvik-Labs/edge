# H3 接收批量化消融（2026-11-02）

本轮对[联合候选](performance-h3-stage2-2026-11-02.md)进行三版本独立对照。**单包消融版出现 12 次传输超时，暂不采用；接收实现恢复至此前的批量候选。整体 HTTP 提速仍未证实。** 批量版本轮 HIT 数值较好，但 OFF 的 CPU 与吞吐明显回退，且各版的 steal、客户端负载不一致，不能据此宣称批量接收普遍更快。

随后独立修复的重试缓冲问题见[修复与诊断](performance-h3-retry-buffer-2026-11-02.md)。下面三个版本均为该修复之前的冻结发行二进制，不把后续源码变更的效果写入本表。

| 版本 | 治理压力读取 | 接收方式 |
| --- | --- | --- |
| baseline | 原完整快照 | 原单包返回 |
| batched | 轻量快照 | 填充多个可用接收缓冲区 |
| candidate | 与 batched 相同的轻量快照 | 恢复原单包返回 |

candidate 指本次单包实验。它与 batched 的 Rust 差异仅为 quic_udp_demux.rs：恢复原 socket 接收实现，并撤回两项专属新批量行为的测试；全部原有错误、ECN、队列记账及 NAT 回归保留。正文、证书、超时和资源准入校验没有放宽。

## 同条件三方对照

载荷 1 KiB，每状态每版本三轮、单场 10 秒、32 连接各 1 在途，每项独立重启目标与 tmpfs。三轮顺序依次为 baseline / candidate / batched、batched / baseline / candidate、candidate / batched / baseline。源站 H1；目标 2 CPU / 2 GiB、客户端 2 CPU、源站 1 CPU，父级总配额 4 CPU。下表为 RPS / CPU µs/成功响应 / P99 ms，各项独立取中位数。CPU 包含目标控制端，不扣除短窗口空闲参考值。

| --- | ---: | ---: | ---: |
| HIT | 4,731 / 267.38 / 17.14 | 6,002 / 211.13 / 11.15 | 4,638 / 243.62 / 21.80 |

批量版相对 baseline：HIT 观测 RPS +26.9%、CPU -21.0%；OFF RPS -35.6%、CPU +75.7%。这些方向不一致的结果全部保留，不用本轮较好的 HIT 替换上一轮较差的 HIT。candidate / OFF 的原始成功吞吐、CPU、成功请求 P99 仍在 CSV，但失败请求不计入成功请求 P99，不能用该 P99 掩盖超时。

## 失败与环境证据

第 16 场（第三轮 candidate / OFF）成功 22,158、失败 12，全部为 curl 28 / HTTP 0，客户端记录耗时约 10.4–14.7 秒。压测窗口连同在途请求结束共 31.72 秒。回源数 22,170，前后 H3 证书验证、完整正文及 BYPASS 探针均通过；因此不能把未完成请求记成缓存命中、成功或零错误。

该场目标 CPU 0/1 的 steal 为 73.5% / 74.1%，客户端 CPU 2/3 为 76.8% / 78.6%；目标 cgroup throttled 时间增加 8.31 秒，源站增加 2.97 秒，目标 memory.events 的 high / max / oom / oom_kill 都为零。日志还包含两次 reusable-stream 获取错误。以上支持环境严重受限的判断，但不能证明没有软件问题，也未证明恢复批量接收能根治超时。

原严格执行器遇到该场即停止；初始索引、非零退出及 traceback 原样保留。后续只执行原计划中缺少的 baseline / OFF 与 batched / OFF，没有重测失败场或延长超时；两场均通过。另分别对单包、批量版各做 7 项功能校验，14 项全部通过。整个容量对照仍是 **17/18 通过、12 个原生传输错误**，不是 18/18。

## 取舍与验证

恢复 batched 是撤回尚未验收的新单包实验，理由包括单包版的一次传输失败及跨轮不稳定；不是根据单个最好 HIT 分数认定性能胜出。此前联合候选的 408 项 Rust 回归、39 项容量及功能记录仍适用其冻结源码；本次 batched 的 6 项容量和 7 项功能场景均通过。长期稳定性仍未验收。

单包消融源码相关 Rust 回归去重 406 项通过、1 项既有测试忽略，Clippy 通过，发行构建完成（31 分 17 秒）。两个版本各自的 7 项功能覆盖 H3 MISS/HIT/OFF、128 KiB MISS/HIT，以及每状态 2048 次新连接的 HIT/OFF，原生错误均为零。未扩大为全仓或完整 RFC 合规验收。

单包二进制 SHA-256：`7fdcb6fbcc9586d08a65404427a084c93df011aeb1774abd3c9effada03bbc93`。批量版为 `8226346bcba3eb8609eba60a4fe61308b10196643ac6d1734e09a00d6c492966`；baseline 为 `f1a38b9003ba868f0f26f5b6fe95b0fa5a12005e37c15a160ff9e3bb46ebb414`。源码 177 项、5 个可执行文件及测量工具摘要均冻结，后续修复不改变这些历史样本。

云构建缓存已按用户授权放宽，原 12 GiB 人为配额不再用于本云工作区，仍保留磁盘可用空间底线。编译与测量串行，被测 CPU、内存和业务缓存条件没有因此调整。

原始 TSV、完整失败、可移植索引、逐轮指标和复算方法见[证据说明](evidence/h3-recv-ablation-2026-11-02/README.md)。Nginx/OpenResty 的完整协议与状态对照保留在[上一轮报告](performance-h3-stage2-2026-11-02.md)，不将不同时段的竞品值混入本组三方排名。
