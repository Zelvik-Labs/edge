# OFF回源系统调用：业务、框架与竞品

未采样的相同48格CPU账本显示H1 Edge内核态约70.62µs/请求，纯Pingora42.99、Nginx39.40。
本轮固定同一ba474 Edge和3b25c01实际纯Pingora、相同既有C客户端，增加H1/H2 OFF两轮反向顺序的16格调用计数；不编译新服务器。
每格全新实例/缓存、1KiB、32并发、10秒，继续核对每个响应、正文/TLS与OFF逐请求回源。

跟踪器使用单独cgroup、256MiB和1CPU配额、无网络，只共享目标PID命名空间。
云runner只有4CPU，跟踪器固定在其中一个客户端CPU；这种竞争以及ptrace本身会显著扰动调度，所有吞吐、延迟和CPU/请求均排除出容量排名。
用已有SyscallProfile逐线程检查TracerPid，负载开始前/完成后均确认覆盖，显式SIGINT后核对全部观测线程已脱离跟踪。
就绪与结束标记原子发布；校验时间顺序、总调用/错误与逐项之和、实际目标ELF及负载有效响应数量。

调用错误包含EAGAIN等正常非阻塞结果，不等同HTTP失败；strace的wall time包含等待与跟踪扰动，不当作内核CPU分摊。
调用计数也不能直接给出每种操作的未采样成本；例如futex计数不区分等待和唤醒，后续仍需结合路径解释。
只公开计数汇总、线程覆盖元数据与fixture响应，不保留系统调用参数/载荷内存。
任何失败保留未压缩/压缩原始响应、partial计数与状态，未执行格不补成零成本。

额外修正固定客户端的来源标注：旧矩阵client_source_sha256取当时检出的C文件，复用历史ELF时不能将其当作该ELF的源文件身份。
旧报告实际客户端始终以固定ELF SHA和provenance的原始build run验证；本轮显式记录a19f6e2源修订/源码SHA，同时保留当前harness C文件SHA，避免混淆。
