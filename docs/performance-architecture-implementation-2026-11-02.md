# Edge 架构优化实现与独立对照（2026-11-02）

本轮把上一份[架构诊断](performance-architecture-gap-2026-11-02.md)中的低风险热路径改造和两项明确的行为调整落到生产代码，并用冻结的旧版、新版生产 release 二进制与 Nginx、OpenResty 独立交叉测试。H1 三轮短测中，缓存命中的每成功请求 CPU 中位数下降约 30%，冷缓存写入下降约 54%，无缓存回源下降约 6%。无缓存回源和缓存命中仍存在明显差距，尚未达到全场景超过两者。

本报告是共享云机器上的探索结果，CPU steal 较高，多组吞吐波动超过 15%；不能据此验收生产容量领先或长期稳定性。冷缓存采用唯一 URL 的有界批次，缓存盘为 tmpfs，尚未验证真实块设备、不可压缩对象、磁盘耐久性或 24–72 小时运行。

## 实现与行为边界

| 改动 | 原因与当前行为 | 边界 |
| --- | --- | --- |
| 请求上下文共享空快照 | 空缓存策略和空编译计划复用 `Arc`，减少每请求默认对象分配 | 当前测量为 2 核；共享 Arc 的多核原子争用仍需另测 |
| 请求过滤状态单一所有者 | 内部异步阶段借用一个 `RequestFilterState`，减少状态在各阶段 future / 返回值之间搬移 | 阶段顺序、拒绝、提前返回与清理语义保留，未完成整个执行链专门化 |
| H1 解析完成标记放在连接任务内 | 生产 H1 连接循环使用 task-local `Cell`，避免每请求地址字符串和共享字典操作 | H2/custom session 不再写无消费者的 H1 标记；兼容调用保留有界旧路径 |
| 变换判断按需构建 | 先判断站点是否有候选优化/HLS/WebP，再创建 URL 或读取全局策略；扩展名大小写比较不分配小写字符串 | 编译计划、原始配置回退、出站 WAF 缓存旁路规则保留 |
| 客户端 IP 候选头预编译 | 复用 12 个类型化 HeaderName，直接访问 HeaderMap | 保留候选优先级、合法性解析与公网直连不信任转发头的边界 |
| 已禁用进程锁不再预备根目录列表 | 生产原本关闭跨进程文件锁，调用方现在也跳过根路径克隆 | 没有移除进程内 purge/key 锁，也没有移除 Bloom 子系统 |
| 缓存临时文件创建合并 | 目录准备和打开文件放进同一个 blocking 任务，减少一次异步文件任务调度 | I/O 失败仍记录警告并按既有契约旁路此次 fill；没有隐藏错误 |
| 已知长度小于 64 KiB 的缓存对象直接存储 | 避免每个小对象构造 Zstd 上下文；未知长度、至少 64 KiB 的合适文本继续流式压缩 | **明确的 CPU/空间取舍**：较小对象会增加缓存写入与占用；已有压缩对象继续可读。HTTP Content-Encoding 不变 |
| H2 正常成功请求不再触发 200 次轮换 | 原来的 30 秒内 accepted≥200 被当成 churn，正常复用也关闭连接；现在累计 rejected+errors≥200 才触发该条件 | 流准入、异常帧/重置保护、空闲超时和最长寿命仍保留；这是已授权调整的保护语义 |

主要代码：[请求链与上下文](../src/proxy.rs)、[H1/H2 连接管理](../src/http_proxy_manager.rs)、[缓存文件与填充](../src/cache_hybrid.rs)、[存储编码策略](../src/cache/storage_encoding.rs)、[客户端 IP](../src/client_ip.rs)。

前一阶段的指标依赖位图、模板编译、响应头按需捕获与漏记修复保留。关闭自定义指标时不构造其专用提取上下文，基础统计继续记录，配置代切换与耐久交接契约未删除。此次整节点配置关闭自定义指标，不能把本表中的收益归因于自定义指标提取优化；相关组件实测见[指标实现报告](performance-extraction-implementation-2026-11-02.md)。

## 如何比较

- 每次只运行一个产品和独立源站；每个协议/缓存/连接/重复场景均重启目标并清空其 tmpfs，失败也保留。
- 目标固定 CPU 0–1、2 CPU 配额、2 GiB 内存；两个原生客户端在 CPU 2–3，源站在 CPU 4、1 CPU 配额。父级 `cpu.max=800000 200000`，实际总配额 **4 CPU**，不是 8 CPU；五个不同 CPU 编号不等于五个独占核。父级内存上限 16 GiB。没有并行编译或其他压测，仍不能把这些分绑核任务视为完全独立的硬件资源。
- Edge 使用实际 `Zelvik-Edge start-internal` 和认证控制端；控制端在同一 cgroup，CPU 计入 Edge 总成本。Nginx/OpenResty 无业务 Lua。所有配置关闭访问日志、业务 WAF、自定义指标，基础统计和内置保护保留。
- 原生 libcurl 客户端逐响应校验协议、证书、HTTP 200 和完整正文。HIT 要求窗口内源站增量为 0；干净 MISS/OFF 要求源站增量等于成功响应数。不会以失败回退来凑吞吐。
- H1/TLS H1/H2 reuse 为 32 连接各 1 在途请求；H2 multiplex 为 2 连接各 16。在所有模式禁用客户端 TLS session cache；使用相同 RSA 2048 位证书，产品默认密码套件/组未强制完全相同。
- 交叉顺序为旧版/新版/Nginx/OpenResty；第二轮相邻反转。每个窗口前记录 2 秒空闲 CPU 参考值，**没有从测量 CPU 中扣除**。这不是完整的服务稳态预热，延迟后台任务仍可能影响较长批次。
- CPU/200 是整个目标 cgroup 的 CPU 增量除以成功响应数，包含内核、后台任务和测试控制端；P99 取原生客户端观测。内存峰值、错误、连接数、源站量、磁盘占用、客户端 CPU 和 steal 均在 CSV/JSON 保留。

## H1：1 KiB、连接复用、三轮

HIT/OFF 每窗口 8 秒；MISS 每批 4,096 个唯一键。下表均为三轮中位数，`CPU` 为 µs/成功响应。

| 场景 | 旧版 RPS / CPU | 新版 RPS / CPU | Nginx RPS / CPU | OpenResty RPS / CPU | 新版 CPU 变化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| HIT | 14,053 / 95.68 | 23,033 / 67.36 | 31,853 / 30.88 | 27,168 / 35.23 | -29.6% |
| OFF | 9,200 / 160.94 | 10,112 / 151.46 | 15,604 / 48.61 | 16,699 / 47.59 | -5.9% |
| MISS | 2,286 / 813.28 | 4,704 / 376.73 | 3,659 / 430.00 | 2,671 / 521.66 | -53.7% |

36 个场景全部通过，零原生错误。新版 HIT 的 P99 中位数为 5.44 ms（旧版 11.21 ms），OFF 为 13.35 ms（旧版 12.90 ms），MISS 为 22.85 ms（旧版 36.24 ms）。OFF 的延迟没有随 CPU 小幅下降而改善。

新版 HIT 的 CPU 仍约为 Nginx 的 2.18 倍、OpenResty 的 1.91 倍；OFF 分别约 3.12 倍、3.18 倍。MISS 短批次的新版本优于这一组对照，但部分新版批次不足 1 秒，因此下面另列 32,768 键复测，避免把短暂突发误报为稳态领先。

## 冷缓存长批次：1 KiB、H1 复用、三轮

每批 32,768 个唯一 URL，所有请求必须真实回源，仍是有界批次。12 个场景全部通过、零原生错误。

| 产品 | RPS 中位数 | CPU µs/200 中位数 | 批次时长中位数 | RPS 最小–最大 | P99 中位数 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 旧版 Edge | 1,964 | 930.32 | 16.68 s | 1,962–2,011 | 44.34 |
| 新版 Edge | 3,734 | 474.92 | 8.78 s | 3,234–4,173 | 27.81 |
| nginx | 6,979 | 240.94 | 4.70 s | 5,372–7,154 | 14.51 |
| openresty | 2,578 | 686.10 | 12.71 s | 1,341–4,246 | 54.31 |

新版 CPU 中位数下降 49.0%，RPS 增加 90.1%。这确认小对象冷写入的组合改造有明显收益；**较长批次中仍未超过 Nginx**，短批次的领先不能延伸成稳定领先结论。OpenResty 在此组三轮波动很大，不能据中位数宣称确定的生产倍数。

旧版批次约 16–17 秒，新版约 8–10 秒，不同批次长度会覆盖不同启动后台任务；窗口前仅 2 秒空闲观测，CPU 不扣后台成本。所有产品最大核心 steal 均较高，客户端和源站的实际资源记录须联查。

## 32 KiB：H1 复用、单轮探索

HIT/OFF 窗口 5 秒，MISS 仅 512 个唯一键、各产品批次均不足 1 秒。12 个场景全部通过、零原生错误；这些 MISS 结果只展示短批次行为。单元格为 `RPS / CPU µs`。

| 状态 | 旧版 | 新版 | Nginx | OpenResty |
| --- | ---: | ---: | ---: | ---: |
| HIT | 15,905 / 100.3 | 17,587 / 91.6 | 16,623 / 50.8 | 27,699 / 35.0 |
| OFF | 7,073 / 261.5 | 8,283 / 210.1 | 14,504 / 75.9 | 13,435 / 82.3 |
| MISS | 1,616 / 1028.9 | 1,908 / 849.5 | 2,319 / 708.1 | 1,599 / 958.2 |

小对象不压缩的代价在这一组出现：512 次 MISS 的数据文件系统占用增量，旧版 2.36 MiB，新版 16.36 MiB（相同高度可压缩文本）。这里是整个挂载点的占用增量，包含元数据等，**不是块设备写入量或纯正文压缩率**。tmpfs 无法验证实际磁盘写放大与耐久性。

64 KiB 是本批采用的初始工程边界，未证明是所有负载下的最佳阈值；32 KiB 的空间放大需要纳入容量预算。HIT 单轮中新版 RPS 高于 Nginx，但 CPU 成本仍明显较高，云环境和客户端限制足以改变吞吐排序，不能据此宣布稳定领先。

## 剩余问题与下一项工程重点

**已修复：** H2 低阈值正常轮换的触发条件；普通请求的多处重复准备；小对象逐次压缩和部分文件调度开销。当前短测验证了收益与错误减少。

**仍存在：** H1 OFF 和 HIT 的 CPU 差距、TLS H1 未显示一致改善；H3 缓存仍为 BYPASS，可靠 body EOF 尚未接入；H3 每请求新连接批量停滞尚未定位；缓存 ENOSPC 与关键遥测共享存储导致 fail-stop 的资源隔离问题尚未修复。本轮未重跑新版完整的新连接容量矩阵，历史[协议/连接报告](performance-protocol-state-comparison-2026-11-02.md)不能替代新版验收。

**设计改造尚未完成：** 整个普通数据面的紧凑执行计划、origin 不变参数预编译、回源准入仅在真实拨号时执行、worker 本地统计聚合、详细分析与内容加工分层、Bloom 整体移除、正文与元信息统一格式。应继续优先围绕 OFF 路径减少 Header/Peer/上下文准备和共享协调；真实拨号准入必须保持 TCP/TLS、503、健康状态和连接池隔离语义，不能简单挪动一个锁。

**明确取舍：** 小于 64 KiB 已知长度文本取消存储压缩，空间/写入成本增加；H2 正常流量不再按 accepted 低阈值轮换。其余内容加工、基础统计、协议校验、缓存一致性与持久确认能力没有整套删除。

下一轮应对新生产构建重新采样 OFF/HIT，并对压缩策略与文件合并做独立消融，再推进 origin/执行计划和详细统计分层。正式领先验收需要低 steal、足够独立 CPU 预算，补齐不可压缩与大对象、完整新连接、慢客户端、重试、配置热更和 H3 真实缓存状态，并分别完成 1 小时、24 小时、72 小时稳定性。当前没有完成这些长期验收，也未发布或部署。
