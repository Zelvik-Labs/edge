# 共享 QUIC 定时清理与准入压力口径

已修正一项源码层面的不一致：共享 QUIC 的准入按全局预算及路由表、待定路由、重组占用共同计算压力，
五秒定时维护之前却只使用全局压力。因此内存/FD 正常、路由表占用超过 70% 时，准入已经收紧，
定时清理仍可能使用 180 秒的普通 H3 元数据期限，无法应用既有的 60/20/10 秒压力期限。
请求路径的压力清理从路由上限 90% 才触发，也不能覆盖 70%～90% 区间的全部情况。

定时维护现在复用同一份 QUIC 压力计算，按既有策略清理过期路由及 CID/session 索引。
路由索引在一次清理中共享一个单调时钟读数，避免逐项重新读取时间；没有据此报告耗时收益。
活跃元数据仍按最后活动时间保留，UDP passthrough 的 60 秒空闲期限保持原定义。

回归使用健康的全局预算、70% 路由占用和合成时间，不阻塞等待：
旧普通策略保留 75 秒前的 H3 元数据；QUIC 压力策略移除过期路由及其 CID 别名，同时保留活跃别名。
该测试和完整节点验证将在 GitHub Actions 运行，本地未进行 Rust 编译。

这项不一致是已确认的代码问题，不等同于证明它解释了此前共享长批次的全部超时。
已保留的超时批次仅有全局压力正常的健康快照，缺少对应的 QUIC 局部占用与拒绝计数。
还需验证高 churn 下的关闭连接路由寿命、状态预算和恢复时间；当前没有新的吞吐或长期稳定性结论。
原生 Quinn 的密钥更新互操作错误是独立问题，本项清理修正不作为其修复。

经审批的功能降级：无。防护、容量上限、准入拒绝及既有压力期限均保留，未扩大超时或隐藏失败。
