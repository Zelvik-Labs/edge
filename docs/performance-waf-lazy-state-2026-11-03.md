## 最终候选的组件结果

七张实际生产 BoundedScopedMap，代表性请求容量 1,677,721/表，实际槽位沿用旧规则
为 1,677,696/表；每种实现每种容量各五个独立进程。这里使用 System allocator，
并非完整 Edge 的 mimalloc 或实际 governor 配额。

| 指标 | 原实现中位数 | 当前候选中位数 |
|---|---:|---:|
| 七张空表 RSS 增量 | 469,778,432 B，约 448 MiB | 24,576 B，24 KiB |
| 构造 | 173.04 ms | 0.013 ms |
| 200,000 次已有键查询 | 3.760 ms | 3.873 ms |
| 200,000 次稀疏已有键查询 | 3.962 ms | 3.917 ms |
| 200,000 次已有键更新 | 4.433 ms | 5.763 ms |
| 稀疏填充阶段 | 14.65 ms | 119.66 ms |
| 稀疏填充后进程 RSS | 471,883,776 B | 302,403,584 B |

所有容量下，空表增量约 24 KiB；稀疏查询中位数变化 -1.14% 至 -0.06%，单键命中
+0.46% 至 +3.01%，已有键更新仍慢约 28%–30%。首次填充的页提交成本后移，不能
只报告构造时间而隐去填充开销。这里的稀疏负载每表最多 16,384 次插入，保留真实
探测窗口淘汰行为。RSS 是整个测量进程的观测，不是精确的单一分配器字节账本。

## 实现与试验记录

1. `304e709` 按 64 槽块分配：空表收益成立，但查询约慢 20%、更新最高慢 72%。
   [实验 41643504991](https://github.com/Zelvik-Labs/edge/actions/runs/41643504991) 全部原样保留。
2. 位图方案：首次写入才为分片保留未初始化槽位，只有占用位允许读取对应 Copy 值，
   无需把所有空槽页写成 None；扫描遍历占用位和活值，空分片整体释放。固定 hash
   地址、八槽探测窗口和原有容量取整不变。首次版本的迭代器闭包编译错误保留于
   [41644177094](https://github.com/Zelvik-Labs/edge/actions/runs/41644177094)，已修复。
3. `dce6292` 对已确认存活的键直接覆盖值，省去重复分配检查与占用位写入。
   实测写入退化仍存在，继续在整机请求路径和更高写入负载中评估。
4. `358a4ef` 尝试用单次条件回绕替代窗口内重复取模。额外保留两次相对 eager
   基线的比较，以及 [同机对比 dce6292](https://github.com/Zelvik-Labs/edge/actions/runs/41660332860)，
   共 90 个进程。相对 dce 的五轮配对中位数：稀疏查询慢 0.79%–1.90%，
   单键查询结果混合，更新从慢 0.65% 到快 8.30%。没有建立整体优势；这些表的
   常见请求以读取为主，因此 `e193f11` 已撤回该候选，保留 dce 的查找/更新实现。
   不把不同 runner 的绝对纳秒差异当作增量收益。

同时修复容量边界：新槽位采用原子预留；跨分片淘汰先取得专用压力锁再锁分片，
避免持有目标分片后互相等待；被淘汰项的全局配额直接转给新项，避免短暂释放后
被另一写入者抢走。已有项面对预算缩小时保留，之后通过替换、过期和移除收缩。

11 项组件测试涵盖配额、淘汰返回值、并发小预算、引用模型 churn、位图尾部边界
及 remove/reinsert。另有 1 项 Miri 测试验证未初始化槽位的访问规则；这不是对
整个 Edge 或全部并发行为的 Miri 证明。完整 Node 测试发现一个依赖调度速度的
旧测试：读端完成 2000 次读取后立即停止写端，导致写端不足 11 轮。已改为 20 个
协调阶段，保留 2000 次读取并执行 2000 次写入，原有最终一致性断言未削弱。

已修复：空表物理预分配、空槽全表扫描及上述容量/锁路径。
