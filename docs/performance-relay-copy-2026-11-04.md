# TCP/SNI 普通转发：部分写入计数与取消清算

普通转发路径现在按已被 writer 接受的字节计数，取消或错误会清算尚未刷新的统计；
两个方向的计数器借用父 future 内存，去掉两个 Arc 分配。这里没有移除基础流量统计。
组件计时中完整写入基本持平或略快，64 字节连续短写慢约 3.81%；这轮的主要收益是计数正确性和少量分配减少。

## 已修复

旧 `copy_stream_and_count` 等 `write_all` 整块完成后才更新累计值，尚未刷新的流量增量只存在普通局部变量中。
因此 `write_all` 部分成功后出错或被取消会漏计已接受字节；等待下次 read 时取消也会丢掉此前未刷新的指标。
新的普通转发与 splice 路径共用 `RelayProgress`，每次成功写入更新累计值，Drop 清算余量。
EOF 时仍先刷新再执行半关闭；WriteZero 仍是错误，原有 benign error 分类没有放宽。

| 确定性控制 | writer 已接受 | 旧累计/旧统计 | 新累计/新统计 |
|---|---:|---:|---:|
| 部分写入后 BrokenPipe | 3 | 0 / 0 | 3 / 3 |
| 部分写入后 WriteZero | 3 | 0 / 0 | 3 / 3 |
| 部分写入后取消 | 3 | 0 / 0 | 3 / 3 |
| 已写完，等待下一次 read 时取消 | 6 | 6 / 0 | 6 / 6 |

旧版精确计数断言以预期的 panic 退出，新版通过；独立日志保留四种控制，不用“测试整体通过”掩盖旧版的失败。
生产测试另外覆盖真实 metrics registry 的相应方向计数、1 MiB 刷新阈值与 Drop 不重复累计。

每个方向的组件调用，分配从 **2 次 / 65,560 字节**变为 **1 次 / 65,536 字节**，没有 realloc。
剩下的分配是固定 64 KiB 复制缓冲；两方向合计少两个计数器 Arc 分配，不能宣称整个 relay 已经无锁或零分配。

| 完整复制组件 | 旧版 ns/次，中位数 | 新版 ns/次，中位数 | 五组配对变化中位数 | 配对范围 |
|---|---:|---:|---:|---:|
| 1 KiB，整块写入 | 841.10 | 835.61 | -0.65% | -1.16%～+1.00% |
| 64 KiB，整块写入 | 3953.60 | 3940.27 | -0.25% | -0.63%～-0.19% |

左右两列是各自进程中位数，配对变化是逐组比值的中位数。短写结果没有被剔除或平均到整块写入中。

## 仍存在

高频短写现在承担更频繁的累计值更新，实测有小幅退步。后续可以研究把父 future 的结果读取安排在子 future 释放之后，
从而合并累计值发布，但必须继续覆盖部分写入、取消、双向半关闭和 splice 观察器生命周期，不能以少报字节换成绩。
tokio 通用 split 的共享所有权、复制缓冲和真实网络调度成本仍存在，本轮未移除。

## 设计限制

探针提取两个提交中的原始方向函数和错误分类函数，候选还提取生产 `RelayProgress`。
固定 64 KiB buffer、关闭压力超时，使用 ready 的内存 reader/writer 和原子指标接收器；
不测实际 governor/指标 map 查找、内核 socket、SNI 握手或 AF_XDP。输入确实复制至输出并校验正文。
每次调用只测一个方向及其计数器所有权模式，不能把纳秒或分配变化直接换算成完整节点吞吐。

Rust 1.99.1、x86-64-v2、opt-level=3，Tokio/libc 及传递依赖版本与 root lockfile 一致。
构建结束后在同一 CPU 上交替五组，10 进程、800 原始块，记录 host steal 为零；
System allocator 计时和分配插桩分开。无 24/72 小时稳定性或真实 NIC 验收结论。
