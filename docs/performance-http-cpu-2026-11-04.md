## 待修复与优化依据

`request_cache_filter` 无条件计算完整对象 hash、读取缓存元数据、检查已存响应头，随后才检查请求是否带 Range。
而这次完整对象探测只决定 Range 使用完整对象还是部分存储。普通 GET 也付出了这项成本。
H1 HIT 中 `stored_response_headers_allow_shared_cache` 包含调用占 5.31%，H2 HIT 为 4.11%；
调用栈能追溯到该准入分支。这是可去掉的重复预检查，不代表缓存存储层原有的安全验证可以删除。
下一轮先将这项探测限制到非空有效文本 Range 请求，并覆盖完整/部分对象、过期、压缩、私有头和禁用部分缓存的原有行为。

MISS 中元数据 writer 占 8.29%～9.81%，同时包含分配、序列化及数据库工作；
需要对批量提交、持久化与 purge fence 做独立验证，不能把异步化误认为这部分 CPU 已经消失。
统计 worker 在 HIT 中仍占 4.51%～5.55%；基础统计与有配置的维度统计必须继续区分，
后续优化应减少上下文构造和重复查找，不能直接少记请求。

## 设计限制

perf 使用 `cpu-clock:u`、199 Hz、DWARF 栈采样；所有采样期间的 RPS、CPU/request 和延迟均排除在容量排名之外。
栈符号中有 7.44%～10.48% 的叶节点为 unknown，含 libc/vDSO；优化和内联也会影响符号归因。
报告保留完整符号表及逐轮值，分组按字符串匹配，仅用于确定候选，不能替代修改前后配对实验。
这不是 24/72 小时稳定性测试，也没有对这轮 Nginx/OpenResty 做同样的 CPU 栈采样。
