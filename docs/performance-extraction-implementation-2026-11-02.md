# 指标热路径实现：编译提取依赖与模板

本轮直接在最新 Edge 基线 `01a2156` 上实现，不依赖 RKE。代码在 `perf/next-20261102` 工作树；没有发行或部署，没有关闭基础统计、安全检查或协议功能。收益主要针对启用自定义指标的请求，尚无完整节点吞吐领先结论。

## 实现

- 配置编译时构建 `RequestFields`：80 个固定字段使用位图，动态/未知变量仍保留完整集合。Header 名称预解析和去重，Cookie/参数名称、响应头匹配名、域名分段位置预先整理；请求侧不再反复扫描配置变量或构造未选中的键。
- 域名分段只提取实际引用的位置，不再为仅使用 `${host}` 的配置创建分段 Vec 和八个临时分段键。Cookie/参数只在选中时创建输出键，值的 trim、解码和重复键覆盖规则保持原语义。
- 完整 Header 字符串使用一个输出缓冲，取消逐行临时 String/Vec；单独 Header 字段直接查询已编译名称，保持第一个合法 UTF-8 重复值的规则。
- 指标模板在配置代内编译，保留文字、变量顺序、未知变量和未闭合表达式语义。单变量键直接返回解析器的 String，避免第二个输出缓冲；占位符判定取消临时格式化字符串。同事件的多个指标共享一次事件分钟计算，报告周期仍由后端控制。
- 采集计划、模板和提取器都随既有不可变配置代发布/持有；旧请求及排队事件继续使用其原配置代。窗口身份、版本、计数、基数/字节上限及耐久交接流程没有修改。

## 修复的统计问题

1. `${http.X-Test}` 原先可能产生 `http.x-test` 属性，而解析器回查 `header.*`，导致取不到维度值。现在 `http.*` 与 `header.*` 共用规范键，修复大小写别名并减少重复字段；历史已产生的空维度不补造。
2. 响应头采集开关原先主要由访问日志决定；日志关闭而指标需要响应头时可能取空。现在同时检查请求持有的指标配置代。禁用指标或仅需要请求字段时，不增加响应头捕获；基础响应头字节统计继续保持。

这两项属于可复现的正确性缺陷；配置依赖反复解析、无关字段键构造和模板二次缓冲属于热路径设计开销。本轮证据能解释这些局部成本，尚不足以归因历史整节点性能差距，也不能据此认定 Pingora 或异步架构本身不合理。

## 组件实测

探针为 `benches/support/request_fields_probe.rs`，直接包含生产提取器/模板模块，并在测量前比较新旧输出。固定到 CPU 2、七轮交替顺序，分配计数另测；原始每轮结果保留，不按结果删除样本。使用同一套 HTTP/mimalloc 依赖，探针自身 opt-level=3、codegen-units=1、panic=abort、x86-64-v2、未启用 LTO，依赖来自 opt-level=2 测试构建；不是整节点 release 压测，也没有初始化整节点 allocator bridge。

| 组件场景 | 旧/新分配次数 | 旧/新 realloc 次数 | 旧/新中位耗时 ns |
| --- | ---: | ---: | ---: |
| 引用 host 但未引用域名分段 | 9 / 0 | 0 / 0 | 531.9 / 3.7 |
| 三个已选域名分段 | 15 / 7 | 0 / 0 | 655.4 / 216.7 |
| 32 个请求头中选两个 | 6 / 5 | 2 / 0 | 1,056.2 / 178.5 |
| 完整请求头字符串 | 36 / 3 | 67 / 7 | 4,504.3 / 896.4 |
| 32 个响应头中选一个 | 34 / 3 | 0 / 0 | 1,692.5 / 499.5 |
| 32 个忽略 Cookie 中选一个 | 35 / 3 | 32 / 0 | 3,088.1 / 1,261.0 |
| 单变量模板 | 2 / 1 | 1 / 0 | 185.3 / 29.3 |
| 混合模板 | 4 / 4 | 0 / 0 | 205.2 / 108.3 |

以上是局部操作，包含刻意突出某项重复工作的场景；不能相加成每请求节约量，也不能把倍数当作 HTTP 提速倍数。时间仍有云环境波动，分配数量更适合核对机制。单变量模板探针不包含完整投影解析器，因此不包括取消占位符临时格式化的额外收益。

## 验证与边界

已通过一轮 opt-level=2 的 86 项指标测试和两项共享请求路径测试。新增覆盖包括全部固定字段选择、动态变量、Header 大小写/非法值/重复值、空/短/长域名、配置代与类别隔离、分析值回退、复合指标的键/窗口/计数/预算释放，以及日志关闭时的响应头依赖。模板还比较了 3,993 个边界组合的输出/变量顺序，并验证单变量直接返回原缓冲。

最终检查结果见验证索引；收口语法后复核根 crate 的测试使用 opt-level=0、依赖仍为 opt-level=2，生产库 Clippy 使用正常 dev 配置，生产 release 配置未修改。原有 target 保留；仅在超出规定预算后使用托管 GC 回收旧增量/对象状态。

复核使用共享 `local-rust.sh`，依次运行 `test --locked --lib metrics::`、`test --locked --lib 'proxy::tests::metric_'` 和 `clippy --locked --lib -- -D clippy::correctness -D clippy::suspicious`。最终两组测试额外传入 `--config 'profile.test.package.zelvik-edge.opt-level=0'`。六个修改的实现/探针文件通过 rustfmt；`src/metrics.rs` 只调整模块声明，保留了基线已有的其他格式差异，没有顺带全文件重排。

本轮未实现新的 HTTP/1 I/O 引擎或连接缓冲池，TCP/UDP 的完整上下文构造未重写；配置编译仍遵循原发布锁，频繁大配置更新的延迟需要单独验证。响应头快照与访问日志、出站 WAF 共用，触发捕获时仍保留完整快照；本轮减少的是指标投影中未选字段的字符串创建，尚未重构该共享快照。完整 Edge 的 H1/H2/H3 节点集成、整体 CPU/请求、P99、Nginx/OpenResty 对照及长时稳定性仍待后续本地/隔离环境验收。
